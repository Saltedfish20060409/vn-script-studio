# 长程一致性、分支结构与评估：这一轮做了什么、量到了什么（2026-09）

> 本文回答一个问题：**"轻小说/视觉小说动辄几十万字，角色、分支、读者、评估这四块，我们到底做到了多少？"**
> 上一轮审计的结论是"前三块是工程化启发式、第四块骨架最亮但站不住"。
> 本文记录这一轮把哪些地方补成了**可量化、可回归**的量具，以及**仍然没做到什么**。

---

## 一、先看被量出来的那个真问题

原来的一致性审计（`backend/app/core/consistency_audit.py`）有两处硬上限：

```python
_CHAPTER_TEXT_CAP = 1600    # 每章只取前 1600 字
_MAX_CHAPTER_TEXTS = 14     # 全书只取前 14 章
```

它是**静默**的：跑一次会得到一份看起来正常的报告，作者无从知道第 30 章根本没被检查过。

现在这件事有了数字。新增的长程基准会造一部带**标准答案**的合成长篇（60 章、22 条埋点、
3 条诱导项），在受控章距上注入矛盾，然后量两件事：

| 方案 | 可见章数 | 暴露率 | 1-3 | 4-8 | 9-15 | 16-30 | 31+ |
|---|---|---|---|---|---|---|---|
| 旧方案（前 14 章） | 14 | **0.14** | 0.50 | 0.17 | **0.00** | **0.00** | **0.00** |
| 分片方案（6 章/窗，重叠 2） | 60 | **1.00** | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 |

- **暴露率**（exposure）＝"矛盾所在的冲突章，有没有被送进检测器视野"。
  这是检出的**必要条件**，而且**不需要任何模型**就能算——所以它能进 CI 当回归量具。
- 旧方案在 9 章以外的暴露率是 **0**：那些章的召回**在构造上**就不可能是 1，
  这不是"模型不够强"，是"根本没给模型看"。

同一份基准上的检测器表现（只跑确定性检查，不调模型）：

```
检测器 detect_deterministic: precision 1.00 · recall 0.64 · F1 0.78 (TP 14 / FP 0 / FN 8)
  A 层（确定性可分）召回 14/14 = 1.00 · B 层（语义，需模型）召回 0/8
  分桶召回: 1-3:0.75  4-8:0.67  9-15:0.60  16-30:0.50  31+:0.67
  分类错但章节对: 0 · 范畴外（结构性 lint）: 0 · 重复命中: 0
```

A 层覆盖 **7 类**确定性可分的问题：死亡后仍出场、时间线错序、未登记说话人、
未声明地点标、**声线走样**、**情感弧线断裂**、**未回收伏笔**——后三类正是
"角色像不像本人 / 弧线有没有走反 / 埋了没收"这三个指标，此前它们只在分析端点里，
**没有标准答案可对照**，现在进了基准并各有回归闸。

B 层（年龄/季节/关系/物件属性）**必须靠模型**，确定性检测器一条也抓不到——
这是"哪些必须上模型"的量化依据。

复现：

```bash
cd backend
set PYTHONPATH=.
python -m app eval --longrange --longrange-chapters 60        # 不需要 API key
```

### 基准反过来抓出了量具自己的两个真缺陷

这份基准的第一个用户是声线量具本身，而它一上来就红了两次。两次都是真缺陷，不是调参：

1. **把 p97.5 当阈值 → 异常越多越查不出。** 留一法的"零分布"是用角色自己的台词建的，
   其中就混着想检测的那些走样章。60 章里埋 2 处走样时，走样台词本身就是分布里最高的那几个值，
   p97.5 落在异常簇内 → 阈值被抬高 → 走样章反而被判成 `watch`。
   改成**中位数 + MAD 的稳健阈值**，并加两条**绝对效应下限**（偏离太小就不值得打扰作者，
   不管统计怎么说）。
2. **画像中心与尺度本身不稳健。** 均值/标准差会被别处的走样台词撑大，
   于是"偏离几个标准差"被稀释——本处异常因为别处异常而显得正常。
   换成**中位数中心 + 1.4826×MAD 尺度**后，四处抽样种子的确定性层召回都从 0.90 回到 1.00。

这两条正是"先建带标准答案的量具、再拿它量自己"的价值：没有基准，这两个缺陷在真实长篇里
只会表现为"偶尔有条声线提示没报出来"，永远不会被发现。

## 二、四个方向的现状对照

| 方向 | 上一轮 | 这一轮 |
|---|---|---|
| **长程一致性** | 关键词检索 + 前 14 章一次性 LLM 扫描 | 分片全量扫描（跨窗合并、覆盖率如实上报）+ 确定性跨章冲突检测 + 卷/全局记忆层 |
| **角色建模** | 人设＝markdown 模板，声线校验＝LLM 主观判断 | 新增**声线指纹**：从作者自己的台词学分布，用留一法自校准阈值，给出可复现的 drift 分数 |
| **分支与规划** | 展示树 + label 字符串边 | 真实 label 图、环检测、分支覆盖、条件可满足性、无后果选项、多结局对账、best-of-N 打分重排 |
| **读者建模** | **完全为零**（试玩器零回传） | 试玩选择持久化（默认关、不存任何正文）+ 读者行为分析 + 分支覆盖（读者视角） |
| **评估** | 只印两臂均值差，裁判与选手同模型，提示里带着答案 | 独立裁判可插、去掉剧透、多种子重复、bootstrap 置信区间 + 符号检验 + McNemar；新增带标准答案的长程基准 |

## 三、新增模块与它们负责回答的问题

### 1. 一致性：`core/consistency_scan.py`

- `plan_windows(project, size=6, overlap=2)`：按章序切成**互相重叠**的窗口，**每个有正文的章节都落进至少一窗**。
- `run_consistency_scan(...)`：逐窗调用（并发上限 4），**单窗失败不拖垮整轮**；
  跨窗合并去重，**同一冲突被多个窗口独立报出 → `confidence: high`**
  （"换个章节组合也成立"比"只被一个窗口报出"更可信）。
- 如实上报 `coverage`（扫了多少章/共多少章/哪几章没扫到）与 `ceilingNote`（直接引用旧的两个常量）。

### 2. 事实一致性（确定性）：`core/continuity_graph.py`

`analyze_continuity(project)` 查这些**不需要模型**的问题：
未登记说话人、悬空的角色/地点关系边、跨角色重名、角色卡存在但全篇没出现、
未声明的场景标、时间线指向不存在的章节、时间线 order 与章节序矛盾、重复时间线事件、
**已记录死亡却仍出场**（启发式，会给证据与说明）。

### 3. 结构推理：`core/branch_analysis.py`

`analyze_branches(project)` 输出：真实 label 图、**环检测**（区分"有出口的 hub"与
"既无变量变化又无条件出口 = 玩家出不去的死循环"）、**分支覆盖率**、
**条件可满足性**（只在能证明"恒不成立"时才报）、**无后果选项**（选哪个都一样）、
软锁菜单（所有选项条件都恒不成立）、结局对账（声明的结局 vs 实际可达终点）、死代码。

### 4. 声线量具：`core/voice_fingerprint.py`

- 从作者**自己已写的台词**学出每个角色的语言分布（句长/小句数/逗号密度/语气助词/疑问感叹省略倾向/敬语），
  不调模型、不用 embedding。
- **阈值自校准**：用**留一法**算出该角色自己台词的 drift 分布，取 p90 / p97.5 作为
  "留意 / 跑偏"的界——多少算偏由作者自己的文风决定，不设魔法常数。
- 评估某章时用**留一章法**建画像（被评估的那一章不参与建模），
  否则越跑偏的章越会抬高自己的阈值，结果是"写得越离谱越判不出来"。
- 另外给出角色两两声线距离，回答"这两个人说话是不是一个味"。
- 边界：这是**风格**量具，不是语义量具。它抓"说话方式"，抓不到"说的话不符合人设"。

### 5. 评估：`core/eval_stats.py` + `core/eval_longrange.py`

- `eval_stats`：配对 bootstrap 置信区间、符号检验、McNemar 精确检验（纯 stdlib，同一 seed 完全可复现）。
- `eval_longrange`：带标准答案的合成长篇基准（含**诱导项**用于量误报），
  分桶给出暴露率与检出率，判分口径写在模块 docstring 里。

### 6. 读者侧：`playtest` 遥测 + 分析

见 `backend/app/api/v1/playtest.py`、`app/services/playtest_telemetry.py`。
**默认关闭、只存 id / 索引 / 布尔 / 计数，绝不存任何正文**；开启后可以看到
每个选项被选次数、玩家在哪一章停下、哪些选项从没人选、哪些结局从没人走到，
以及"读者实际走过的选项数 / 剧本可用选项数"这一个**读者视角的分支覆盖率**。

隐私是**四层**的，不是口号：① 没有显式开启记录的工程，record 端点直接 403 且不落任何行；
② 表里没有自由文本列，所有字符串过 `^[A-Za-z_][A-Za-z0-9_.:-]{0,63}$`（中文会被丢成空串），
未知字段一律丢弃并回显字段名；③ 不存 IP / UA / 指纹 / user_id，只存客户端随机 `client_run_id`；
④ 分析与上报都**不回选项文案**，只有 `menuId` + `choiceIndex` + 计数——换来的是
"整条链路零正文"可以被测试机检。

### 7. 长篇记忆第三层：`core/global_memory.py`

现有记忆只有"每章抽取式摘要"与"每 10 章归档"两级，四十章之后没有"整本书到目前为止"的压缩表示。
新模块按卷（没有卷就按跨度）聚合，给出每卷的章节范围、字数、**按重要性排序的出场角色**、
关键事件与**未回收伏笔**，再拼一条模板化"到目前为止"总述。纯本地、不调模型，
因此挂在 Agent 每轮上下文里，超预算时优先保留总述与未回收伏笔，并如实标注省略了哪几段。

重要性带**时间衰减**：

```
base       = 出场章数 + 1.5 × 承担章末钩子的章数
recency    = 0.25 + 0.75 × 0.5 ** (距最后一次出场过了几章 / 8)
importance = base × recency
```

不加衰减时重要性是**静态累加**——第 3 章退场的角色到第 40 章分数还是原样，
于是"谁**现在**还重要"答不准（这是这一层此前最明显的缺口）。半衰期 8 章，
掉到 0.25 就不再掉：**不是抹掉退场角色**（他可能回来），只是"当下这卷里他没那么重"。
衰减相对**本档末尾**计算，不会拿全书最后一章去压早期的卷；角色在档内最后一章还出场时，
算式里不出现衰减项（作者不必看一堆 ×1.00）。

### 8. 故事层指标：`core/story_metrics.py`

另有两个作者会直接问、但此前完全没有量具的指标：

- **伏笔回收率**：账本其实一直在记 open/paid 的伏笔，却从没有人把它算成一个数——
  于是"埋了 20 个钩子只收了 6 个"只能靠一条条数。现在给出回收率、
  未回收清单（按"挂了多久"排序）与最老钩子的章龄。**没有伏笔时返回 `null` 而不是 0.0**：
  没有伏笔不等于"回收率 0%"。
- **情感弧线**：逐角色按台词推断"开头情绪 → 结尾情绪"，并在能取到节拍表时与
  `emotionStart` / `emotionEnd` 的**声明**对账，区分两类问题：
  `arc_flat`（声明有变化、实际一点没变）与 `arc_reversed`（方向写反）。
  情绪靠关键词推断，因此只报明显不一致、且每条都带证据句；节拍表里的词对不上就**不猜**。
- **逐章弧线断裂**：整部作品级的弧线答不出"哪一章把他写反了"，而后者才是作者能直接改的。
  所以另给一份**逐章**情绪走向（每章至少两句台词才评估，一句话推不出走向），
  并报出"局部走向与全篇相反"的那些章（`emotion_arc_break`，带 `chapterId`）。
  判定保守：全篇本来就平的、该章本来就平的，都不报——前者是 `flatArcs` 那条提示的事，
  后者只是"这一章没写情绪"。
- **未回收伏笔逐条**：除聚合的回收率外，每条未回收伏笔单列一个带埋点章的 finding
  （`foreshadow_unresolved`，封顶 20 条），这样前端能按章展示、基准能按章归因。

> 这里同样修掉了一个"静默死功能"：`story-metrics` 的"声明弧线 vs 实际弧线"对账要读
> `harnessRuns` 里的节拍表，而运行历史的记录里**根本没有 `beatSheet` 字段**——
> 那个对账在生产里永远返回空。现在 `run_pipeline` 与 `finalize_chapter_async` 都会把
> 节拍表一并落库（只留对账需要的几个字段），并有从"写历史"一直到"能报出对账问题"的端到端测试。
>
> 另外，写端点级测试时还抓到一条**污染回收率的既有缺陷**：账本自动派生章末钩子时
> 只判了 `len(closeHook) > 4`，而 `chapter_digest` 会把结构块渲染成 `[label start]`
> 这类方括号标记——于是一个"只写了一个 label 的空章"也会被记成「章末钩子（自动）」。
> 后果有两层：空章被算成"埋了没收"（回收率凭空变差），以及那条假钩子会进
> `format_ledger_for_agent` 的未回收清单、**当成事实喂给写作模型**。
> 现已改为"去掉方括号标记后仍须有正文才算钩子"。

### 9. 分支改进建议（融合）：`core/branch_recommendations.py`

上面两条数据源本身都只是"事实"：`branch_analysis` 说**结构上**哪里写坏了，
读者遥测说**经验上**读者怎么选。作者要的是"该怎么办"，所以这一层把两者融起来，
产出按优先级排序、每条都带 `why`（依据）与 `action`（具体改法）的建议。

融合才看得见的东西——同一个"某选项 0 次被选"的观测，配上不同结构结论完全不同：

- 它和其它选项**后果相同** → 「直接删掉它，或者给它一个真实后果」；
- 它只是**文案不吸引人** → 「先确认它到底可不可见，再改文案让收益更明确」。

只看读者数据说不出这个区别，只看静态结构则根本发现不了"没人选"。

三条防误读的设计：`basis` 明确区分 `script-only` / `script+readers`；
试玩次数低于 `min_runs`（默认 10）时**拒绝做经验判断**并在 `sampleNote` 里说明理由
（小样本下的"没人选"说明不了任何事）；每条建议带 `confidence`（`static` / `evidence`），
有读者证据才算证据。

### 10. best-of-N 采样 + 确定性重排：`core/pipeline/candidates.py` + 流水线接线

以前写作链路是"单次采样 → 确定性检查 → 改写一轮"，没有多候选、也没有打分重排。
现在 `run_pipeline(candidates=N)` 会用**温度梯形**多采几份，再用**确定性量具**排序选优：
分项含 lint 错误/警告、节拍覆盖、**声线偏离**、AI 味、长度；硬错误权重恰好等于软项之和，
所以"有 error 就一票否决"是权重算术的结果而不是排序特判。默认 N=1（关），
开启时 N 封顶 6，并把 N、温度、每份得分、选它的理由与**成本提示**全部写进返回值。

### 11. 自适应选项：`core/adaptive_reader.py` + 导出器开关

"剧情随读者历史变化"此前完全没有，而它通常需要作者先给每个选项打标签（要改模型 +
编辑器 UI，成本高且容易没人用）。这里换一条路：**从现有的 `set` 块自动派生**。

某个选项本来就会改 `affection`，那就说明"这个读者的选择体现了一种倾向"。
导出时（`export_to_renpy(project, adaptive_reader=True)`）在该选项体内自动追加一行

```renpy
$ persistent.reader_tendency_affection += 1
```

于是作者**不需要任何新 UI**，就能在后续选项的条件里直接写
`persistent.reader_tendency_affection >= 3`，得到"老是心软的人更容易看到某条支线"。

三个刻意的取舍：

- **用 `persistent` 而不是普通变量**：普通变量随存档各自独立，`persistent` 才是
  "这个玩家在所有存档里的一贯倾向"——自适应要的是后者。
  （实现时这里漏过一次 `persistent.` 前缀：导出看着像在计数、实际每次读档从 0 开始。
  现在有专门的回归测试锁死它。）
- **默认关闭**：这是会改变导出产物语义的开关，必须显式开启，
  否则"同一份剧本两次导出结果不同"会让作者困惑（默认路径逐字不变，也有测试锁）。
  入口在导出端点上：`GET …/export/rpy?adaptive_reader=true` 与 `…/export/bundle?adaptive_reader=true`。
- **不碰试玩器**：试玩器仍按作者写死的条件演（它没有跨局状态），自适应只作用于导出后的 Ren'Py。

`GET …/analysis/adaptive-plan` 给出：值得做成自适应的菜单（结合"无后果"与"一边倒"）、
计数器清单、以及可直接照抄的条件示例。

> 实现时踩到两次"做完了却打不开"的坑，都补了回归闸：
> ① 注入语句漏了 `persistent.` 前缀（等于每次读档从 0 开始）；
> ② 导出器支持这个参数，但**两个导出端点都没传它**——功能做完了没有任何入口。

| GET | `/api/v1/projects/{id}/analysis/adaptive-plan` | 否（自适应选项：读者倾向计数器 + 条件示例） |
| POST | `/api/v1/projects/{id}/analysis/consistency-scan` | **是** |
| POST | `/api/v1/projects/{id}/playtest/record` · `GET/PUT …/playtest/settings` · `GET …/playtest/analytics` | 否 |
| GET | `/api/v1/projects/{id}/playtest/recommendations` | 否（静态分析 + 读者行为的融合建议；`min_runs` 控制经验判断门槛） |

前端入口：分析/报告区的 **「深度体检」** 子标签（分支推理 / 声线 / 跨章事实 / 全书一致性），
面板按需请求、不自动打接口。

## 五、这一轮**没有**解决什么（照实写）

1. **跨几十章的长程关联仍在窗口之外**。分片法的固有上限：一窗最多同时看 6 章，
   第 2 章的伏笔与第 40 章的回收永远不会出现在同一个窗口里。重叠只保护相邻边界。
   基准里的 `exposure` 量的正是这件事的下界，别把它读成"全覆盖"。
2. **单章内部仍截断**：单章超过 1600 字的部分不进模型。现在会**如实报出**被截断的章，
   但内容确实没看。
3. **"设定漂移"型问题抓不到**：每条单看都不违反、跨几十章累积起来才违反的一致性
   （口吻慢慢跑偏、称呼渐渐变化），逐窗读文本发现不了。
4. **语义矛盾必须靠模型**：年龄/季节/关系/物件属性这类，确定性检测器召回为 0（基准已量化）。
   而且 LLM 扫描的去重靠字符串归一化，跨窗复发是**下限**而非精确计数。
5. **声线量具只管风格**：句长与助词能算，但"这句台词不像她会说的话"仍需要人或模型判断。
   台词少于 8 句的角色直接拒绝给结论（算不出分布）。
6. **best-of-N 的成本是刚性的**：N 份就是 N 次调用，并发只压缩等待时间；
   确定性打分能选出"更干净"的那份，但抓不到语义层面的好——两份都干净但质量差距大时，
   分数可能相同，winner 会退化成"取温度较低的那份"。
7. **读者建模仍缺偏好学习与自适应**：现在能回答"玩家实际怎么选"，
   还不能回答"该给这个玩家推什么"——协同过滤、偏好向量、MAB/分流都还没做。
   而且为了隐私**刻意不存读者身份**，跨设备/跨清缓存无法把两次试玩关联成同一个读者。
8. **评估的 n 仍然小**：AB 用例 13 条，即使加了置信区间也只能说"区间很宽"。
   要真正支撑结论需要更多用例与人类评分（`docs/blind-ab.md` 仍是未填写的工作纸）。
9. **全局记忆不是语义压缩**：它是模板拼装，主线到底是什么仍要读者自己拼；
   重要性已有时间衰减（见第三节），但**出场依据仍只是"在该章说过话"**——
   只在旁白里被提到、从无对白的角色进不了名单，纯 prose 工程的角色层会是空的。
10. **建议引擎的射程是"结构 + 行为"，不是语义**：它能说"这个选项选哪个都一样"
    "没人走到这个结局"，说不出"这段反转不成立""这句台词不像她会说的"。
    「没有建议」不等于「剧本没问题」，API 的 `notes` 里写明了这一点。
11. **匿名读者路径仍未接**：试玩遥测目前只有工程成员能上报（见 `api/v1/playtest.py`
    开头的鉴权说明），分享链接的读者匿名上报需要 token 校验 + 更严的限流，属于后续工作。
    也就是说"读者行为"里的数据，目前实质上是**作者自己试玩**的样本。
12. **自适应选项（按读者历史动态调整分支）**：已落地**自动派生的读者倾向计数器**——
    某个选项本来就会改 `affection`，导出时就为该选项追加
    `$ persistent.reader_tendency_affection += 1`（用 `persistent` 所以跨存档），
    作者不必给选项打标签，就能在后续条件里写 `persistent.reader_tendency_affection >= 3`
    做自适应。`GET …/analysis/adaptive-plan` 给出候选菜单、计数器清单与可照抄的条件。
    **导出默认不开**（`export_to_renpy(..., adaptive_reader=True)` 才注入），
    否则同一份剧本两次导出产物不同。
    仍未做的部分：**试玩器不模拟 persistent**（它没有跨局状态），
    所以"自适应"只在导出后的 Ren'Py 里生效；同理，读者倾向也还没有进入读者行为分析。

## 六、顺手发现的既有行为（留档供决策）

**CI 的体积门禁曾经是红的，现已通过（真做了代码分割，没有改门槛）。**

门槛是 `.github/workflows/ci.yml` 那一步：`dist/assets/*.js` 压缩前 > 500KB 即失败。
当时的产物里 `StudioApp-*.js` 是 **576.44 kB**（会话开始前那份旧 dist 也已是 557.7 kB），
超限约 12.6%，而且**不是配置能绕过的**——运行时依赖只有 react / react-dom /
react-router-dom / react-markdown / remark-gfm 五项，其中 react-router 已并入 `react`
chunk、react-markdown 已单独成 chunk，`StudioApp` 里基本全是应用自己的代码
（`StudioApp.tsx` 三千多行 + 静态引入的一百多个组件）。

**解法**：把「只在切页签 / 开窗口 / 进桌面视图时才渲染」的大面板做懒加载，
并用**同名包装组件**包一层局部 `<Suspense>`（调用点的 JSX 一行都不用改；
也不能只在路由层兜底，否则切页时整页闪成 fallback）：

| chunk | 改前 | 改后 | 说明 |
|---|---|---|---|
| `StudioApp-*.js`（首屏） | 576.44 kB | **322.37 kB** | 首屏少下约 241 kB raw（gzip 193 → 109 kB） |
| `AgentChat-*.js` | （在首屏里） | 84.83 kB | 只有打开「AI 责编」窗口才加载 |
| `CharacterWorkshop-*.js` | 同上 | 54.33 kB | 只有切到「角色」页签 |
| `AnalysisPanels-*.js` | 同上 | 41.60 kB | 只有切到「分析」子页签 |
| `MapStudio-*.js` | 同上 | 38.63 kB | 只有切到「地图」页签 |
| `LocalizationPanel-*.js` | 同上 | 19.68 kB | 只有切到「本地化」子页签 |
| `DesktopView-*.js` | 同上 | 16.36 kB | 只有进入桌面模式 |

CSS 也随之下沉（面板各自的 `*.css` 与 chunk 配对）。以上数字来自本机真实构建
（vite + PWA）；门禁那一步现在跑是 `OK: 全部 dist/assets/*.js <= 500KiB raw`。

**另一件仍然没做的事**：`docs/engineering-review-2026-09.md` 记的「nginx 没开 gzip」
尚未修（实测能省 61%），与本条独立。

**`run_pipeline(stages=["write"])` 仍会发 LLM 请求。**
流水线结尾**总会**计算 quality gate；当 `check` 不在 `stages` 里时，它会回落到
`stage_check_async(...)`，而该函数的 `voice_check` 默认为 `True`、`semantic_beats`
默认为 `True`——于是"只跑写作阶段"实际上还会再打一到两次模型。

证据：写 best-of-N 的接线测试时，一个只跑 `stages=["write"]` 的用例耗时 **13 秒/例**；
用 `cProfile` 定位到 `httpcore → anyio.connect_tcp → socket.getaddrinfo`（DNS 解析占 7.3 秒），
也就是测试真的在连一个不存在的 base URL。把结尾的 gate 也打桩之后，
同样 5 个用例从 13 秒降到 **0.04 秒**。

- 这**不是本次引入的**：`run_pipeline` 的这段回落逻辑早于本次改动。
- 但 `stages` 的文档写的是"Run selected stages"，与"仍会为 gate 付费"不完全一致，
  调用方若想靠 `stages=["write"]` 省成本会失望。是否收紧（例如仅在显式要求 check 时才回落）
  属于产品语义决策，因此本次只记录、不改行为——改了会静默改变既有调用方拿到的 gate 含义。

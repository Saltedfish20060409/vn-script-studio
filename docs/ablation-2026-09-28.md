# 单块消融实测（2026-09-28）

第一次回答"craft / 写作导师这两块到底值多少分"。共跑了两轮：
**第一轮裁判不独立**（同模型自评，只作基线）；**第二轮换成独立裁判**（选手=服务端 glm，
裁判=DeepSeek）并且加了 chat 用例集与 `craft_lean` 臂——第二轮才是能当依据的那一轮。

原始报告是本地产物（与 `docs/ab-report.json` 一样不入库：`.gitignore` 忽略 `docs/*`，
只白名单几个 md）：
- 第二轮（独立裁判）：`docs/ablation-arms-report-independent-judge.json`
- 第一轮（同模型裁判）：`docs/ablation-arms-report.json`

复跑命令见文末。

## 第二轮：独立裁判（`judgeIndependent=true`）

- 选手：服务端免费的 `glm-4-flash-250414`；裁判：`deepseek-v4-flash`（**另一个模型**）
- 16 个用例 × 4 臂（`tool` / `craft_lean` / `no_mentor` / `bare`），`--repeats 1`，seed 20260409
- 用例三类：chat 讨论 3（线上最常见的请求类型）、retention 保留集 3、boundary 边界集 10

| 集合 | n | tool（基准） | craft_lean | no_mentor | bare |
|---|---|---|---|---|---|
| chat | 3 | **1.47**（veto 1） | 1.33 | 1.00 | 1.00 |
| retention | 3 | 1.40（veto 1） | **1.93** | 1.40 | 1.33 |
| boundary | 10 | **1.72**（veto 4 · lint 90%） | 1.30（veto 5） | 1.68（veto 2） | 1.06（veto 6 · lint 60%） |

与基准的配对差（95% bootstrap 区间）：

| 集合 | craft_lean − tool | no_mentor − tool | bare − tool |
|---|---|---|---|
| chat | −0.13 [−0.40, 0.00] | −0.47 [−1.00, 0.00] | −0.47 [−1.00, 0.00] |
| retention | +0.53 [−0.20, 1.80] | +0.40 [0.00, 0.80] | −0.07 [−0.80, 0.60] |
| boundary | −0.42 [−0.94, 0.08] | **−0.04** [−0.56, 0.42] | **−0.66 [−1.12, −0.20]（不含 0）** |

### 怎么读

1. **裁判一独立，绝对分整体下移**（同口径 1.0–1.9，而第一轮同模型裁判给的是 2.4–3.6）。
   这说明第一轮那些好看的分里，有相当一部分来自"自己给自己打分"。**以后只认独立裁判的读数**。
2. **写作导师块测不出效果**：boundary 上 `no_mentor − tool = −0.04`（几乎为零），
   retention +0.40、chat −0.47 都是小样本噪声。它每轮要花约 1.6k token，而收益测不出来
   → 已给它加上开关（「⚙ 资料」里的「写作导师方法论」），并建议**线上默认关掉**。
3. **craft 精简（详述 17 → 6，省约 1.3k 字）方向不一致**：boundary −0.42（更差）、
   retention +0.53（更好）、chat −0.13，全部跨 0。**不能据此改默认**；`detail_max`
   作为旋钮留着，等 `--repeats ≥ 3` 再判。
4. **第一次在独立裁判下得到"整条流程更好"的证据**：boundary 上 `bare − tool = −0.66`，
   区间不含 0，且 veto 6 vs 4、lint 通过率 60% vs 90%。范围仅限"照写问题写法"的陷阱集——
   chat / retention 的 n=3 太小，方向一致但不足以下结论。
5. chat 集是这轮新增的（线上 55/60 次运行都是 chat）：tool 1.47 vs bare 1.00，
   方向支持"讨论请求上也有用"，但 n=3，只能说"没发现反例"。

## 第一轮（同模型裁判，仅作基线）

13 用例 × 4 臂（tool / no_craft / no_mentor / bare），裁判与选手同模型
（报告自带 `judgeIndependent=false` 告警）：

| 集合 | arm | lint 通过 | Rubric | veto | 配对差 vs tool |
|---|---|---|---|---|---|
| retention n=3 | **tool** | 100% | **3.60** | 0 | — |

| | no_mentor | 100% | 3.47 | 0 | −0.13 [−0.20, +0.00] 跨 0 |
| | bare | 100% | 2.80 | 0 | −0.80 [−0.80, −0.80] |
| boundary n=10 | **tool** | 100% | 2.78 | 1 | — |
| | no_craft | 90% | 2.66 | 0 | −0.12 [−0.32, +0.00] 跨 0 |
| | no_mentor | 100% | 2.70 | 1 | −0.08 [−0.20, +0.00] 跨 0 |
| | bare | 70% | 2.78 | 3 | −0.07 [−0.40, +0.20] 跨 0 |

这一轮里 craft 的**确定性部分**有可测效果：摘掉 craft 后 lint 通过率 100% → 67% / 90%，
那是 `backend/app/core/pipeline/style_skill.md` 的禁用词表与落笔自检清单在起作用
（它们同时被 `lint_style_skill()` 做成确定性检查）。结论：**规则在提示词里，检查在代码里**，
两者要一起看——只看提示词会以为"craft 没用"。

## 要变成结论，还缺什么

1. `--repeats ≥ 3`：现在 `rubricValues` 已经记下来了，可以直接看采样方差；
2. 更多**写作类**用例（现在 10/13 是边界用例，对 craft 的考验不充分）；
3. 裁判换成与选手不同厂商、且固定版本（这轮已做到"不同模型"，还没做到"多裁判取一致"）。

## 复跑

```bash
# 本地（需要 DEEPSEEK_API_KEY）
python -m app.cli eval --ab --arms tool,craft_lean,no_style,no_mentor,bare \
    --repeats 3 --judge-model deepseek-v4-flash --judge-base-url https://api.deepseek.com \
    --judge-api-key $KEY --out docs/ablation-arms-report-independent-judge.json

# 服务器上（容器里跑；--independent-judge 会自动取 backend/.env 的开发 key 当裁判）
python deploy/run_ablation.py --arms tool,craft_lean,no_mentor,bare --independent-judge --wait
```

臂的含义与"要摘掉哪一块"的对应关系，见 `backend/app/cli.py` 的 `AB_ARMS` 注册表
（`tool` = 线上等价，含写作导师块；`craft_lean` = 详述只留 6 条；
`no_style` 只摘 `style_guide.md` 那段）。

# 单块消融实测（2026-09-28）

第一次回答"craft / 写作导师这两块到底值多少分"。原始报告是本地产物
`docs/ablation-arms-report.json`（与 `docs/ab-report.json` 一样不入库：`.gitignore` 忽略 `docs/*`，
只白名单几个 md）。复跑命令见文末。

## 设置

- 13 个用例 × 4 臂：`tool`（基准，线上等价）/ `no_craft` / `no_mentor` / `bare`（裸聊）
- 模型：站内免费档 `glm-4-flash-250414`；seed `20260409`；`--repeats 1`
- 裁判：**与选手同模型**（报告里 `judgeIndependent=false` 并自带告警）→ 分数含自偏好
- 用例构成：3 个保留集（正常续写/写戏/改写）+ 10 个边界集（指令要求"照写问题写法"）

## 怎么读（这份报告本身就是为防"把噪声当结论"写的）

1. **单块都不显著。** 摘掉 craft 或导师，分数方向一致地下掉（−0.27 / −0.13 / −0.12 / −0.08），
   但每条区间都跨 0；n=3 的保留集尤其说明不了问题。所以现在只能说
   **方向一致、未达显著**，不能说"已验证有用"。
2. **craft 的确定性部分有可测效果。** 摘掉 craft 后 lint 通过率从 100% 掉到 67% / 90%——
   那是 `backend/app/core/pipeline/style_guide.md` 的禁用词表与落笔自检清单在起作用
   （它们同时被 `lint_style_skill()` 做成确定性检查）。这是本轮唯一"看得见"的效果。
3. **与裸聊的差距比旧报告小得多。** `docs/ab-report.json`（2026-09-21，`deepseek-chat`）
   当时是 boundary 2.9 vs 1.1、veto 0 vs 9；同口径这次是 2.78 vs 2.78、veto 1 vs 3。
   模型不同、单次采样、同模型裁判都可能是原因。
   **因此旧报告"整条流程显著更好"的读数不应被当作已确立的事实**，它至少高度依赖模型。
4. 边界集的 lint 命中率高不代表写得差（用例指令就是"照写问题写法"），所以边界集的优劣
   只看 Rubric 与 veto——报告里的 `summaryNote` 已写明这一点。

## 要变成结论，还缺三样

1. **独立裁判**：配 `CRITIC_API_MODEL` 或 `--judge-model`，报告会保留 `judgeIndependent` 标注。
2. **重复采样**：`--repeats 3`（现在报告会记 `rubricValues`，可以看采样方差）。
3. **更贴真实用途的用例集**：现在 10/13 是边界用例，对"写正文"这类 craft 真正该发挥作用的
   场景考验不足；应该补正常续写/写戏/改写的长用例。

## 复跑

```bash
# 本地（需要 DEEPSEEK_API_KEY）
python -m app.cli eval --ab --arms tool,no_craft,no_style,no_mentor,bare \
    --repeats 3 --judge-model <独立模型> --out docs/ablation-arms-report.json

# 服务器上（容器里跑，key 用服务端环境）
python deploy/run_ablation.py --arms tool,no_craft,no_mentor,bare --wait
```

臂的含义与"要摘掉哪一块"的对应关系，见 `backend/app/cli.py` 的 `AB_ARMS` 注册表
（`tool` = 线上等价，含写作导师块；`no_style` 只摘 `style_guide.md` 那段）。

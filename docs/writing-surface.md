# 写作界面（编辑手感 / 稿件体检 / 轻小说路径）

本文记录 2026-02 这一轮"写作界面"改造：做了什么、边界在哪、怎么验证。
配套的模型侧能力见 [长程一致性与评估](./longrange-consistency-and-eval.md)，
超时预算见 [LLM 超时预算](./llm-timeout-budget.md)。

---

## 一、起点：三个被实测确认的痛点

这一轮不是"想做点新功能"，而是三个具体到能复现的问题：

1. **改不了稿。** 正文在一个 `<textarea>` 里，`spellCheck={false}`。浏览器自带的 Ctrl+F
   搜不到 textarea 里的文字——想改一个角色名、统一一种标点，只能靠肉眼翻整章。
2. **中文标点没人管。** 半角逗号贴在汉字上（`你好,世界`）、`--` 当破折号、`...` 当省略号、
   引号只写了一半，这些在导出成 Word 或继续生成时才会暴露（引号不配对会把后面的正文
   一起吞进台词）。工具此前的体检只覆盖"AI 腔/叙事"层，不管标点。
3. **写到哪了不知道。** 没有字数目标（代码里搜不到 `targetWords`），也没有分场导航
   （大纲在设定页，正文里没有"这一场从哪开始"的锚点）。长篇写作最需要的"今天写了多少、
   这一章还差多少"，工具一个字都没说。

另外还发现：**帮助只有一份**，是写给视觉小说作者的（顶栏写着剧本 / 角色工坊 / 地图），
轻小说作者进来要先学另一套术语，也不知道怎么开始（没有任何轻小说起步模板——
`create_demo_project` 给的是「雨夜车站」这种剧本工程）。

## 二、P0：编辑器手感（纯前端）

新增 `frontend/src/lib/editorAssist.ts`：**纯函数层**，无 DOM、无 React，全部可单测
（`editorAssist.test.ts`，55 项）。组件只负责"把结果画出来 + 把光标放回去"。

| 能力 | 入口 | 关键取舍 |
|---|---|---|
| 查找 / 替换 | 编辑器内 `Ctrl/Cmd+F`（编辑器里有选中文字时，直接当查找词） | 逐个替换 / 全部替换 / 区分大小写 / 正则；正则模式下 `$1` 按标准语义展开，非正则模式下 `$1` 就是两个字面字符。非法正则**不抛异常**，界面显示"正则写错了"——作者是边打边看的，抛异常会把整块界面炸掉 |
| 中文标点自动配对 | 正文模式自动生效（RPY 模式关闭） | 敲左引号/括号补右半边；有选区时把选区包起来；敲右半边而右边正好是它时**跳过**（不重复插入）。输入法组字中、带修饰键一律不接管 |
| 一键插入常用标点 | 写作页辅助条 | `……` `——` `「」`（中文输入法里这两个都不顺手） |
| 分场导航 | 写作页辅助条「分场」 | 认 `◇◇◇` / `***` / `---` 这类分隔行，也认 `【场景名】`、`场景：xxx`、`第 3 场 告别`；点一下跳到该场。**注意**：`第X场` 的判定刻意收紧——宽松正则会把正文首句「第一场的内容。」当成标题，把整章第一个场景切掉（这条有专门的回归测试） |
| 字数目标与进度 | 写作页辅助条「目标」 | 本章（实时字数）/ 本卷（`/stats` 的卷累计）/ 今日（`/stats` 的当日净增）。目标存在作品里（`VnProject.writingGoals`）→ 换设备也在 |
| 笔误体检 | 写作页辅助条「笔误」 | 引号不配对（error，**按段**判：对白跨行合法，按行会误报）、半角标点贴汉字、`--`、单个 `—`、`...`、`。。。`、汉字间空格、行尾空格（后两类是 info）。点条目跳到该处。语义好坏**一概不判** |

实现细节里值得记一笔的两条：

- **字数口径不重复实现。** `editorAssist` 直接复用 `lib/wordCount.ts`（与后端
  `services/writing_stats.py` 同一套规则）。自己再写一份，界面上迟早会出现
  "卷头 1200 字、进度条 1188 字"。
- **正文改动只有一条路径。** 手打、语音转写、一键插标点、插入分场标记、查找替换，
  全部走 `applyEditorText()`：RPY 过期标记、标记失效校验、自动保存一个都不漏。
  在此之前语音转写那条路是自己拼字符串的——少写一项就会让作者在"看起来改了其实没存"
  的状态里工作。

### 持久化：一个新字段要改四处（这是本仓库的既有约定）

`VnProject.writingGoals` 这类项目级字段，漏任何一处都会**静默丢数据**：

1. 后端模型 `app/domain/types.py`（`WritingGoals` + `VnProject.writingGoals`）；
   后端 `normalize_project` 只透传**已声明**的字段，没声明就丢。
2. 后端 `services/projects.py` 的 `MERGE_SECTIONS`——章节级局部保存只接受白名单内的
   section，"只改了目标"的保存会被丢掉，界面还以为存上了。
3. 前端 `lib/vnLocal.ts` 的 `normalizeProject`（白名单式重建）。
4. 前端 `lib/projectDiff.ts` 的 `SECTION_KEYS`（不在这里就不算"有改动"，压根不会保存）。

`vnLocal.ts` 里原本就写着这条警告，这次照办。

## 三、P1：稿件体检（离线统计，不调用模型）

新增两个纯函数模块（都无网络、无 await、无模型）：

- `app/core/novel_consistency.py` — 表记：半/全角与空格混用、引号配对与顺序、破折号、
  省略号写法、**人名变体**（与角色卡/别名/设定条目比对，命中已知写法一律豁免）、
  视角偏移、称呼漂移（后两项标 heuristic）。
- `app/core/novel_craft.py` — 文面：注音写法（`｜汉字《注音》` / `{汉字|注音}`）、
  拟声与感叹密度、**章末钩子 0–1 评分**（末段类型/长度/收尾标点/账本记账四项加权）、
  对白占比与段落长句、逐章相对读数。

三处入口，都是薄壳：

- 路由 `POST /projects/{id}/analysis/novel-audit?parts=consistency,craft`（不消耗配额）。
- Agent 工具 `novel_audit`（`scope` / `chapterRef` / `focus`），返回**线索**而不是结论。
- 前端「项目 → 稿件体检」面板（懒加载分块）。

设计上的三条硬约束：

1. **两组检查互补而不是替代。** 带模型的一致性审计（`/consistency/scan`、`/consistency/audit`）
   回答"这段设定和前面矛盾吗"，离线体检回答"这里是不是敲错了"。前者贵、要配额、要等；
   后者几十毫秒，可以每改完一章点一次。
2. **`coverage` 如实说话。** 扫了几章、哪几章没正文、哪几章因为超上限被截断、问题是否被
   截断显示——全部回传并在界面上写明。一个"全绿但只扫了前三章"的面板比报错更坏。
3. **启发式必须自曝。** 视角/称呼/钩子评分都带 `heuristic: true` 与 `disclaimer`，
   逐项给出 `basis`；`notes` 里写清已知误报风险（例如 2 字名字可能把同首字的常用词
   报成变体、对白密集章天然偏第一人称）。

## 四、轻小说路径

- **起步模板**：`app/core/ln_template.py` 生成一份可直接开写的长篇骨架——1 卷 3 章、
  正文（`prose`）已写、节拍表与预置伏笔在账本里、世界观与术语表在设定条目里。
  注册为模板 `light_novel`（模板选择器直接就能看到）。
  它是"函数式模板"：每次取用都是新对象，且**不参与** `build_from_template` 的章节 id
  重分配——模板里的设定条目 `links`、账本伏笔、运行记录都引用着章节 id，重分配会把引用
  全部打断。这条约束有测试守着（`tests/test_novel_audit_surface.py`）。
- **帮助分路**：帮助面板顶部加「视觉小说 / 游戏脚本」与「轻小说 / 网文」两个开关。
  轻小说那条给 9 步上手 + 5 条 FAQ（"我没写过游戏脚本，那些面板要管吗""投稿要什么格式"
  "写到几十万字还记不记得住前面"）。文案由测试锁死：不出现 rpy/menu/label/jump/试玩/立绘
  这类术语，每一步指向的界面位置必须真实存在。

## 五、连载工作台（P1-6）

`项目 → 连载 / 发布`，回答连载作者每天真正要问的三件事：**今天写了没有、断了几天、
手里有几章能发**。纯函数层在 `frontend/src/lib/serialization.ts`（25 项单测）。

- **连续更新天数**：允许"今天还没写"不算断（从昨天往回数）——否则作者每天早上打开都会看到
  「连续 0 天」，那是纯粹的错误反馈。最长连续另算。
- **更新日历**：近 12 周，**按周对齐**（周一起），因为连载的节奏单位是"这周更了几章"，
  不是"最近 30 天"。
- **口径**：「写了」= 当天净增 > 0（与「写作统计」同一份后端逐日记录）。它量的是
  "今天往前写了"，**不等于"今天发了新章"**；删字、只改标点的日期会有记录但不着色。
- **发布状态**：`SceneChapter.publishedAt`（记时间而不是布尔——连载作者会回头改已发布的章，
  改完再发一次，记时间才看得出"这一章什么时候发的"）。**只有作者能标**，工具不去猜
  哪一章"像"发过的；撤回是把字段删掉而不是置空串，否则"未发布"会有两种表示。
- **节奏预估**：只在作者自己设了单章目标、且样本 ≥3 天时给结论；样本不足一律显示"样本不够"。
  编一个数字出来比不给更糟。

### 这一页逼出来的两个后端缺陷（做的时候就发现了）

`writing_activity` 是热力图与这一页的**唯一数据源**，而它在小说作者的使用路径上原本是空的：

1. **记录口径只数脚本块**：`sync_chapter_rows_from_vn` 用 `count_blocks_words(ch.blocks)`
   算字数增量，而纯正文写作的章节 `blocks` 只有一个 label → 前后都是 0 →
   `record_activity` 见 `delta == 0` 直接 return，**一个字都不会被记下来**。
   改成与面板/连载页同一口径（`count_chapter_words`：正文优先，正文为空才数脚本块）。
2. **日期按 UTC 记**：东八区用户在本地 00:00–08:00 写的字会落到前一天，
   「今日净增」在早上永远是 0。现在客户端通过 `X-TZ-Offset` 头带本地偏移
   （`buildApiHeaders` 统一带，避免以后新增保存路径漏掉），后端按**作者当地日期**记账；
   取不到偏移时退回 UTC（老客户端行为不变），偏移量夹在 -12h..+14h。
3. 顺带修掉一处"注释吃掉了代码"：`put_project` 里那句"事务内行锁防 TOCTOU"的
   `await db.refresh(row, with_for_update=True)` 当时被并进了上一行注释里，从未执行过。

这三条都有测试守着（`backend/tests/test_writing_activity.py`，
`frontend/src/api/tzOffset.test.ts`）。

## 六、投稿包导出（P1-7）

`GET /projects/{id}/export/submission`（`app/core/export_submission.py`，11 项单测 + 3 项路由测试）。

与已有的 `/export/docx` 的分工：那条是"把作品读出来"的通用导出（作者自己看、存档），
排版中性、行为一字未改；这条按投稿方的格式要求来：

| 选项 | 默认 | 为什么 |
|---|---|---|
| 首行缩进 2 字符 | 开 | 中文投稿惯例（小四正文 = 12pt，缩进 24pt） |
| 每章另起一页 | 开 | 编辑按章读 |
| 文末标字数 | 开 | 编辑常问"这章多少字"，省一轮往返 |
| **带上章节梗概** | **关** | 梗概是写给自己看的备注，混进稿子会被当成正文——投稿场景里最容易犯、又最难自己发现的错 |
| 作者名 / 联系方式 | 空 | 留空就不写这一行，不编造 |
| 分章打包 `.zip` | 关 | 很多渠道要求**一章一个文件**；包内是 `第01章_标题.docx` + `投稿信息.txt`（逐章字数与发布状态） |

脚本块工程也能投：投稿稿只出故事文字（旁白 = 正文段、对白 = 「名字：台词」），
`[场景：…]`/`[选项]` 这类舞台指示**不进投稿稿**——那是给引擎看的，想看完整结构去「导出 → 工程包」。

## 七、作品体裁 → 界面用词（P2-11）

写小说的人看到"剧本 / 选项 / Ren'Py / 试玩"的第一反应是"这不是给我用的"，哪怕他要的
功能全都在。`frontend/src/lib/genreCopy.ts` 把界面用词按**作品体裁**分成两套
（剧本 / 正文·分卷·投稿），14 项单测。

三条设计约束（都写在文件头，改之前请先读）：

1. **依据是"这是哪一类作品"，不是"当前在看哪种稿"**：一本小说的脚本模式不该把界面切回
   "剧本"。所以看 `project.writingGenre` 与 `genre`，与 `writeMode` 无关。
2. **显式选择优先**：设定页可选「自动 / 视觉小说 / 轻小说」，自动项会写明"现在是按题材猜成
   哪一套"；没选过才按 `genre` 关键词猜。
3. **默认不变**：老工程一律保持原来的视觉小说用词。这个方向不能用错——把正在写 VN 的
   作者界面改成"投稿"比反过来更糟。`视觉小说` 含「小说」二字，所以 VN 关键词要先判掉
   （第一版就栽在这里，测试钉住了）。

`writingGenre` 是项目级字段，和 `writingGoals` 一样要同时改四处：后端模型 +
`MERGE_SECTIONS` + 前端 `normalizeProject` + `SECTION_KEYS`。

## 八、别字提示（P0-1 剩余部分）

原始反馈是"拼写检查被主动关掉了"。这条分两步做：

1. `spellCheck` 按稿件类型给值（正文开、RPY 关）——浏览器自带检查依赖系统词典，
   中文召回率一般，它标的是"可能写错"。
2. `frontend/src/lib/typoRules.ts`：**确定性词表**，收 80 条成语/固定搭配的同音别字
   （「迫不急待」「一如继往」…），命中即报、给建议写法，并进写作辅助的「笔误」那一行。

收录标准极严：错写形式在中文里不作为另一个词存在、正确形式是唯一公认写法、错写形式不是
专名。**刻意不收**反应/反映、需要/须要、想象/想像、制订/制定、图象/图像——它们同样常写错，
但判定需要语境，词表做不到零误报。一个会误报的错别字提示，作者用两天就会整个忽略掉。
要覆盖那部分得靠模型，不在这一层假装能做。

词表有**两份副本**（架构决定，不是偷懒）：前端 `frontend/src/lib/typoRules.ts` 在打字时跑
（写作辅助的「笔误」行随输入更新），后端 `backend/app/core/typo_words.py` 在全书体检时跑
（`novel_consistency` 逐章给行号与原文，Agent 工具 `novel_audit` 与「项目 → 稿件体检」
面板因此也能报别字）。`backend/tests/test_typo_words.py` **直接解析 TS 源文件逐条比对**，
两份一分叉测试就红——否则作者会遇到最难查的那种 bug：一边提示、另一边不报，而两边看着都对。

别字在后端**逐条单独成问题**，不走同 code 合并：合并后一条消息里只剩"共 N 处 + 几个样本"，
而每个别字要给的恰恰是"它应该怎么写"。

## 九、多变体改写（标记批改）：按证据选，不按"第一版"

写作页的标记卡片可以一次要 2–3 版改写（`processMark(id, 3)`）。这一条的行为改过两次：

- **改前**：一次调用要求模型输出 JSON 数组，取 `variants[0]` ——"模型先写的那一版"，
  是**输出顺序**，与质量无关；而且只有一个响应，logprobs 覆盖整段 JSON，
  **每版都没法单独算置信度**。
- **改后**：N 次**独立并发采样**（温度阶梯铺开），每版各自过自检、各自算置信度，
  再按证据排序（`core/variant_select.py`，依据见 [docs/references.md](references.md)
  的 Best-of-N 一行）。卡片上：

  - 版本按钮显示"**推荐 · 第 N 版**"（推荐版是排序第一，`replacement` 也是它）；
  - 悬停显示证据：综合分 / 模型置信度 / 与其余候选的一致度 / 温度 / 字数 / 问题；
  - 有一版没通过确定性检查（长度失控、丢专名）时按钮带 ⚠，并**排在通过检查的版本之后**
    （一票否决，对齐 `pipeline/candidates` 的硬错误处理）；
  - 对照区上方给一行后端写的取舍说明：**这次用了哪些信号、缺了哪些**
    （没 logprobs 的档位会明说"未测量"——`lib/markVariants.ts` 守住了
    "不把未测量显示成 0.00"，否则作者会以为"模型完全没把握"）。

成本如实写在这里：N 版 = N 次调用（输出 token 与"一次要 N 版"同量级，输入重复 N 次，
局部片段的输入很小）；温度步长 0.15，比候选流水线（0.35）保守——局部改写要求
"不改变信息与情节"，跨度太大容易写出跑偏的版本。

## 十、P0-4 分场导航：为什么没做侧栏大纲

评判的结论是**保留横条并给它一个折叠开关，不改成侧栏**：

- 它的实际用途是"跳到我正在写的那一场"与"在这里插一个分场标记"——都是**就地**动作，
  横条紧贴正文上方，点到即跳；侧栏解决的是"一屏纵览全部场景"，那是**另一个场景**。
- 写作页已经是三栏 + 悬浮 Agent 面板，再加一列会直接挤掉正文宽度；而正文宽度对写作者
  的价值高于"同时看到 20 个场景标题"。
- 真正需要纵览时该去的是「结构分析」（那里有整章结构），而不是在编辑器边上再开一列。
- 但它确实占掉正文上方一条空间，所以加了**折叠开关**（状态记在本机 localStorage，
  不跟作品走）——"占地方"这个批评是成立的，回答是让它可以被收起来，而不是换个地方占。

## 十一、明确没做的

- 场景导航只做"读 + 跳"，不做拖拽重排、不做场景级元数据（POV/时间/地点）挂载。
- 字数目标只有三档（本章/本卷/今日），没有"连续打卡奖励""目标历史"。
- 别字提示只覆盖词表那 80 条；同音字混用、方言写法、自造词都不在射程内（需要模型）。
- 稿件体检面板不做筛选/排序（线索多了只列前 80 条并写明还有多少条）。
- 连载工作台不做"定时发布""多平台同步"——它只在本工具里记账。
- 投稿包不做投稿信的模板生成，也不猜目标平台的字数限制。

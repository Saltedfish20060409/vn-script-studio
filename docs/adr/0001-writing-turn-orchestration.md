# ADR 0001：Writing Turn Orchestration

**状态**：Accepted  
**日期**：2026-10-02  
**决策者**：产品负责人 + 工程协作  

## 标题

Writing Turn Orchestration：以写作质量为目的的方案 B 主链路重做

---

## 1. 背景

VN Script Studio 的 Agent 已具备责编工具环、独立写作通道、设定入库、上下文预算、作家透镜等能力，但**写作主链路体验未形成相对 DeepSeek 网页版的竞争力**（操作便捷度与输出文本质量均不可接受）。

根因不是「缺几个边界功能」，而是：

- 写通道上下文过瘦（对话史空转、作品记忆不足）；
- 审阅通道协议过重，并把「成稿」赶出对话；
- 意图白名单造成通道心智税；
- 续写默认复用整章改稿对照，呈现模型错误；
- **写作 prompt / 透镜 / 压缩质量未作为一等公民专项治理**。

纯方案 A（补缺口）被否决。允许 breaking change；允许删除拖累写作体验的实现；若方案 B 证伪可升级方案 C。

## 2. 决策

1. **方案 B 为主**：统一 Writing Turn / Capability 路由，重做写作主链路编排与交互。
2. **方案 A 补齐**：保留并增强预算引擎、apply 闸、lenses / craft / style_skill、ledger / 记忆、改编检查表、设定抽取协议。
3. **保留方案 C 权限**：若 Turn 层达不到跨模型盲测通过线，可全模块重写；不为兼容保留已证伪代码。
4. **目的与手段**：架构是手段，**写作质量是目的**。优先级见 §4。
5. **数据兼容底线不可破**：现有项目的设定、角色、lore、章节正文必须可被新 Agent **读取**；允许 API/协议 breaking，不允许工程数据静默丢失或读不到。

## 3. 第一期 / 第二期范围

### 3.1 第一期 · 核心（阻塞「写作主链是否可验收」）

| 编号 | 内容 |
|------|------|
| **P0** | 本 ADR 合入 + 回滚演练清单建档 |
| **P1** | `POST …/agent/turn` 骨架（SSE）；**协议层软超时事件 + 硬取消信号**；写作默认走 turn；旧 stream 默认隐藏。**P1 对 write 为透传代理**（见下） |
| **P2** | 写路径注入对话史 + 作品记忆上下文（替换「仅章尾 1200」为主路径） |
| **P2.5** | **写作 prompt 专项** + **轻量盲测夹具**（见 §5） |
| **P3** | 草稿流式进对话气泡 + 轻确认写入；**气泡暴露取消按钮与超时提示**（对照降为高级） |
| **P4** | Capability 路由 v1：`write` / `critique` / `ingest` / `chat`；其中 **`write` 仅先支持 `continue` 与 `rewrite`** |
| **P5** | 补齐 writeOps：`polish` / `expand` / `condense` / `style_transfer`（**P4 未过 P2.5 不得进入 P5**） |

**P1 脚手架说明**：P1 turn 对 write 为**透传代理**，仅用于打通协议、软超时与取消语义；真实上下文与 prompt 改造从 **P2** 开始。P1 **不引入长期技术债**：透传层在 P2 后**退化为兼容层**（见附录「执行说明 1」——**不删除**，以免破坏 B1 回滚路径）。

### 3.2 第一期 · 扩展（仍属第一期，**不阻塞**核心盲测验收）

| 编号 | 内容 |
|------|------|
| **P6** | 结构化 critique + VN/LN 体裁分流（`writingGenre` 必做） |
| **P7** | 多源 ingest + Diff 确认即写入；字段白名单见 §7；LocationLink 放 P7 尾部、非阻塞 |

### 3.3 第二期

| 编号 | 内容 |
|------|------|
| **P8** | **仅**命名档 UI（标准/增强/最大）+ 高级数字 + **成本可见性**（不再承载软超时） |
| **P9** | **线上指标埋点 + 自动化**；**不再是盲测包本身**——盲测夹具已在 P2.5 |

## 4. 工作优先级（质量校准）

任何与下列冲突的「架构优雅」让路：

1. **写作 prompt 质量**（system、透镜注入、风格迁移、上下文压缩）
2. **写通道上下文**（对话史 + 作品记忆）
3. **草稿呈现**（流式进对话 + 轻确认；含取消/超时提示）
4. **路由与 API 统一**（turn / capability）
5. **其余**（ingest 完善、命名档 UI、线上埋点等）

## 5. P2.5 写作 prompt 专项 + 轻量盲测夹具

独立于「把 API 接起来」。交付物：

1. **Writer system prompt 修订**：对话即写作、体裁感知、输出即为可写入正文（无 JSON 劝退）。
2. **透镜注入策略**：本轮 active lenses 如何进入 write profile（长度上限；冲突优先级：style_guide > mentor > lens）。
3. **风格迁移 op**：`style_transfer` 的 prompt 契约与回归样例（契约可在 P2.5 定稿；完整产品化随 P5）。
4. **压缩质量**：超预算让位后，压缩块必须可还原意图（留痕 + 关键事实不丢）；用固定长篇夹具测「压缩前后续写一致性」。
5. **基线对比与轻量盲测夹具**（第一期自我验收，不依赖 P9）：
   - 夹具存 **`docs/writing-prompt-baseline.md`**。
   - **固定 ≥10 条提示词**，至少覆盖：续写、改写、润色、扩写、缩写、风格迁移、设定冲突续写、VN 体裁、LN 体裁、长上下文续写。
   - **每条注明期望维度**（便捷度 / 质量 / 设定一致性 / 速度 / 成本 中的哪些适用）。
   - **人工对比表 + 五维打分表**（人工可跑即可；打分者见附录「执行说明 2」）。
   - 以 DeepSeek 网页同提示词输出为基线，逐项记录本产品改 prompt 前后变化。

**基线模型钉死与跨模型条件（§5）**：

- 盲测基线以 **P2.5 启动当日** DeepSeek 网页默认模型为准，记录**模型名、快照日期、区域设置**。中途网页端模型升级**不影响**本基线；如需换基线，须**重跑全部用例并留痕**。
- **跨模型盲测时，本产品侧必须使用与 DeepSeek 网页默认模型不同的模型**（如 Claude / GPT / Gemini 中当前最强一档），并记录本产品侧**模型名与版本**。
- **若本产品侧使用 DeepSeek API，则视为同模型对照，不计入跨模型主结论，仅作控制变量。**（避免「本产品默认 DeepSeek API vs 网页 DeepSeek」退化成同模型或「同厂不同版本」假跨模型，从而得出「本产品赢了」的假结论。）

未完成 P2.5（含夹具与至少一轮符合上文归类的人工五维打分），不得宣称「写作质量已因架构重做而提升」，且 **不得进入 P5**。

## 6. 目标体验（摘要）

- 默认自然语言 → **turn**；无「写作通道 vs 审阅通道」心智。
- 旧 `/agent/stream` 工具环：**默认完全隐藏**；仅高级设置入口；**不进**写作默认路径。
- 流式正文进对话气泡；写入语义显式（章末追加 / 替换选区 / 替换整章）；轻确认；经典对照为高级。
- **软超时**：P1 协议发事件；P3 UI 可取消并提示；不允许无软上限的无限等待。
- 设定写入：先 Diff，确认后写入工程（**不再二次待审**）。
- 体裁：默认 `VnProject.writingGenre`（及既有题材推断）；每轮可覆盖。

### 6.1 P4 / P5 Capability 与 writeOps 边界

| 步 | `write` 支持的 writeOp |
|----|------------------------|
| **P4** | **仅** `continue`、`rewrite` |
| **P5** | 追加 `polish`、`expand`、`condense`、`style_transfer` |

- P4 同时落地 capability 路由骨架：`write` / `critique` / `ingest` / `chat`（后三者可为 stub 或薄委托，但路由表存在）。
- **门禁**：P4 完成且 **P2.5 通过** 后，才允许进入 P5。

## 8. 上下文档位（P8；数字口径）

| 档位 | 含义 |
|------|------|
| **标准** | **当前默认**：同步 128k / 流式 256k 字符 |
| **增强** | **当前天花板**：同步 192k / 流式 512k |
| **最大** | **模型窗口夹逼，不设产品硬上限**；仍受上游窗口与超时预算约束；数字按实测钉死 |

- 保留高级数字覆盖。
- **成本有压力时：可见成本提示，不砍档位。**
- **最大档 + 长上下文**：本轮给出 token/成本**估算**（**P8** 交付；P1–P5 可先打日志/事件字段预留）。
- **软超时不在 P8**：见 §13.1。

## 9. Breaking change 与数据兼容

### 9.1 允许破坏

API（含 `AgentRunIn`）、会话 schema、设置字段、前端意图协议——见 B1–B6。

### 9.2 不可破坏（数据兼容底线）

新 Agent **必须能读**：

- 项目设定（bible / meta / writingGenre）
- 角色卡与 aliases
- lore 条目
- 章节正文（`prose` / `blocks` 既有 `chapter_plain` 口径）
- 既有会话消息文本（至少只读展示与写入 prompt）

禁止：改存储形状导致旧项目打开后正文/设定为空，或 Agent 只读到空工程。若需迁移，必须写 Alembic/归一化，并带回滚迁移。

### 9.3 B1–B6 与回滚演练要求

每项 flag **必须有演练记录**（时间、操作者、步骤、结果、耗时），模板见 §12。演练归档于 `docs/adr/drills/`。

| ID | 变更 | Flag / 双路由 | 回滚演练要点 |
|----|------|---------------|--------------|
| B1 | 新 `…/agent/turn`；旧 write/stream deprecated | `AGENT_TURN_DEFAULT=true`；旧路由保留 | 关 flag → 前端改指旧 API → 续写仍通 |
| B2 | 消息/请求扩 capability、writeOp、scope、genreOverride | 新字段 optional | 旧客户端缺省行为可接受或 410 文案 |
| B3 | `context_budget_tier` + 保留 chars | tier 优先 | 忽略 tier，回退 chars/服务端默认 |
| B4 | ingest 禁止静默直写 | `INGEST_DIRECT_APPLY` 默认 false | 紧急开直写仅限事故；演练确认 Diff 路径可恢复 |
| B5 | 前端意图/Capability 协议 | `AGENT_LEGACY_INTENT` | 开后恢复旧分流；金样例复测 |
| B6 | 草稿 UX（气泡 vs 对照） | `AGENT_CLASSIC_REVISE_UI` | 开后续写回对照面板 |

## 10. 成功度量：「超过 DeepSeek」五维分立

**禁止**混成单一「综合偏好」百分比作为唯一门禁。五维分别定基线与通过线。

| 维 | 主测（跨模型） | 辅测（同模型） | 第一期核心通过线 |
|----|----------------|----------------|------------------|
| **便捷度** | 本产品（非 DeepSeek）vs DeepSeek 网页默认 | 同 API 同模型（含本产品 DeepSeek API） | ≥70% 试写认为更少步骤完成「正文进工程」 |
| **质量** | 同上 | 同上 | **二选一**：（A）≥60% 偏好本产品；或（B）≥50% 偏好本产品 **且** 设定一致性维度显著领先。**删除「或平局」。** |
| **设定一致性** | 同上 | 同上 | 冲突题上本产品遵守/纠错率**高于**网页版 |
| **速度** | 同上 | 同上 | 首 token P50&lt;3s；常规写作 P50≤60s；重任务软上限 180s、硬取消≤210s |
| **成本** | 估算对比 | 同模型 token | 标准档成本可解释；最大档有预估提示；不因省钱暗砍档 |

- **跨模型盲测 = 主结论**（产品是否真赢）。
- **同模型对照 = 控制变量**（架构/prompt 改动是否有效）。
- **第一期自我验收**：在 **P2.5** 用轻量夹具 + 人工五维打分完成；**不依赖 P9**。
- **P9**：线上指标埋点与自动化，补充而非替代盲测。
- `eval --ab`：回归护栏，非唯一标准。
- P6/P7 **不阻塞**第一期核心写作相关盲测。

**基线模型钉死与跨模型条件（§10）**：

- 盲测基线以 **P2.5 启动当日** DeepSeek 网页默认模型为准，记录**模型名、快照日期、区域设置**。中途网页端模型升级**不影响**本基线；如需换基线，须**重跑全部用例并留痕**。
- **跨模型盲测时，本产品侧必须使用与 DeepSeek 网页默认模型不同的模型**（如 Claude / GPT / Gemini 中当前最强一档），并记录本产品侧**模型名与版本**。
- **若本产品侧使用 DeepSeek API，则视为同模型对照，不计入跨模型主结论，仅作控制变量。**

## 11. 后果

- **正**：写作默认路径变短、上下文与 prompt 成为一等公民；第一期即可用 P2.5 夹具自我验收；跨模型条件避免假胜利。
- **负**：Agent 前端/API 变动大；双路由期维护成本上升；跨模型盲测需配置非 DeepSeek 的本产品侧模型。
- **风险**：重写期质量抖动 → 用 P2.5 基线表、五维人工打分、B1–B6 演练缓释。
- **非目标（第一期）**：外部 skill 市场、协作共写、重做全 pipeline、角色工坊重做；P8/P9 为第二期。

### 13.1 软超时职责分配

| 步 | 职责 |
|----|------|
| **P1** | SSE：**软超时事件** + **硬取消信号**（协议层）；单测覆盖 |
| **P3** | UI：取消按钮、超时提示 |
| **P8** | 不负责超时；只做档位 + 成本 |

性能口径：常规写作软上限提示约 **180s**；硬取消 ≤ **210s**；首 token 目标 P50 &lt; 3s（P1 保证协议可测，达标验证随写路径完整后量）。

## 14. 为什么允许删代码

唯一标准：是否让五维（尤其质量与便捷度）更接近或超过 DeepSeek 网页版。已写 ≠ 有效。证伪的互斥意图通道、过瘦写通道、续写强制对照、静默 ingest 直写、写作默认进工具环，可删可换。

## 附录 A：执行说明

### 执行说明 1：P2 透传层 → 退化为兼容层，不删除

§13 P2 门禁原写「删除或退化为兼容层」。结合 B1「旧路由保留」，**删除透传层会破坏 B1 回滚路径**。

**明确**：P2 起将 P1 透传层**退化为兼容层，不删除**。真正删除须等 B1 旧路由（`/agent/write`、必要时 `/agent/stream`）在**第二期之后**正式下线，并完成对应回滚演练归档。

### 执行说明 2：P2.5 盲测执行者

§5「人工五维打分」指定如下：

- **盲测打分者** = 用户本人（或用户指定的第三方）。
- **Cursor / Agent 职责** = 准备夹具、跑两次（或多次）输出、整理对比表；**不打分**。
- 若第一期只有单评估者，须在 ADR 附件或 `docs/writing-prompt-baseline.md` 记录 **「单评估者非双盲」**，避免误读为严谨双盲实验。

### 执行说明 3：跨模型盲测与非 DeepSeek API Key（可能阻塞第一期验收）

§5 / §10 要求跨模型盲测时本产品侧不得用 DeepSeek API。

- **用户**需提前准备 Claude / GPT / Gemini 中当前最强一档的 API Key。

**UX 留痕（本轮不改 UI）：**

1. **脚本面写入不污染 prose**：切回正文档会显示旧 prose，可能误以为「写丢了」。后续 UX 需「未同步」提示。E2E 必做：切 rpy 面写入 → 切回正文档，确认正文档未变。
2. **prose 面 append 不洗原 blocks 结构**（末尾追加 raw）；但后续 **replace 会全文重排**，洗掉结构资产（label id、menu id、characterId）。此为既有 replace 行为，**不在本 PR 修复**。若用户频繁 append→replace，结构资产会累积丢失。后续 UX 可考虑 append 时对原始 raw 做锚定，或 replace 前提示将丢失结构。
